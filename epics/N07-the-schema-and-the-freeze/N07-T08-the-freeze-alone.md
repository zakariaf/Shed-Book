## 1. Why this task exists

`make gen` **in full** — `build_runner` plus `drift_dev make-migrations` — run once,
writing `kSchemaVersion`, `drift_schemas/drift_schema_v1.json`, `lib/core/db/schema_versions.dart` and
`test/drift/generated/**`. Plus the **schema half** of `withdrawal_has_no_default_test.dart`: decision
#52 puts §12.1 on the snapshot itself, and this is the only moment that assertion can first be
written.

> ### ⚠ This commit is the point of no return.
>
> `04 §1` item 1: the first committed snapshot **freezes the storage representation of every column in
> it**. Every later version is diffed against this file by `SchemaVerifier`, forever, including in 2029
> on a phone that has never been online. There is no server-side backfill, no feature flag, no remote
> kill switch, and no support channel that can fix a bad migration on someone else's phone in April.
> `00-README` §7.1: losing `drift_schemas/` is **unrecoverable**.
>
> **Before you run `make gen`, read the checklist in 5.3 gotcha 1.** Everything on it is free to change
> today and a full table rebuild tomorrow.

### 5.2 The commands, and what each writes

```make
gen:
	$(DART) run build_runner build --delete-conflicting-outputs
	$(DART) run drift_dev make-migrations
```

`make-migrations` is a wrapper. When you need to understand what it did, or need one part of it, these
are the three underlying commands. They take their paths from `build.yaml`
(`databases: shed_book: lib/core/db/database.dart`, `schema_dir: drift_schemas/`,
`test_dir: test/drift/`), so `build.yaml` and these must agree or the artefacts land in the wrong
directory:

```bash
# Writes drift_schemas/drift_schema_v1.json for the current schema.
dart run drift_dev schema dump lib/core/db/database.dart drift_schemas/

# Writes the compressed step definitions used by stepByStep().
dart run drift_dev schema steps drift_schemas/ lib/core/db/schema_versions.dart

# Writes the test helpers the from→to matrix and the data-integrity test use.
dart run drift_dev schema generate --data-classes --companions \
    drift_schemas/ test/drift/generated/
```

### 5.3 The details that are easy to get wrong

1. **The pre-flight checklist. Run it before `make gen`, not after.** Each line is free today and a
   full table rebuild tomorrow.

   | Check | Ruling / source |
   |---|---|
   | All four of `00-README` §5.2's schema-shaped questions carry a ruling with a date | N00-T04. Items 10 (`WithdrawalTarget.milk`), 11 (the temperature column), 13 (`lambs.became_ewe`), 15 (ease 5 vs 6) |
   | P1's `struck` / `struck_at` are on every table the ruling names | N00-T05 |
   | `lambings.declared_birth_type` is nullable with no default | R6 |
   | All seven quad-carrying tables have `captured_at`, `original_effective`, `time_source` and **both** paired CHECKs | R37 — `Lambings`, `Treatments`, `CareEvents`, `EweObservations`, `PenOccupancies`, `FosterEvents`, `Notes` |
   | `media_assets.relative_path` carries all three CHECKs | R62 |
   | `app_settings` has `last_reconcile_scheduled` and `left_handed` | R40 |
   | `treatment_withdrawals` has both `meat` and `milk` targets | 00-README §5.2 item 10 |
   | No `DEFAULT` and no `clientDefault` on `treatment_withdrawals.days` | Decision #52 |
   | `store_date_time_values_as_text` absent from `build.yaml`; no `dateTime()` column anywhere | Decision #29 |
   | Four `@DataClassName`s present; no `…ie` / `…che` row class compiles | R7, R20 |
   | Which drift#3322 fallback shipped is **recorded** in 03 §9.2 and doc 04 | T07 gotcha 5 |
   | Which FTS5 probe shipped is **recorded** in 03 §1.3 | T01 gotcha 6 |

2. **Start from a clean tree.** `git status` empty before you run anything. The whole value of step 4
   is that `git status --short` afterwards shows you **exactly** what `make gen` wrote — and that list
   is what you commit.
3. **Do not bump `kSchemaVersion`.** It is `1` and stays `1`. There is no v0 to step from and no
   `from1To2` callback to write. Bumping it here produces a `drift_schemas/` with one file and a
   `kSchemaVersion` of 2, which `snapshot_count_test.dart` catches — and which, if it ever shipped,
   means `stepByStep` has no callback for the skipped hop.
4. **Never hand-edit anything under `drift_schemas/` or `test/drift/generated/`.** They are generated
   evidence, committed so CI can diff them and so `SchemaVerifier` can build a v1 database in 2029. If
   the JSON is wrong, the **schema** is wrong: fix the table file, run `make gen` again, and commit the
   regenerated artefact. Editing the JSON to make a test green produces a repo whose snapshot describes
   a schema that has never existed.
5. **Assert against the JSON, never against the Dart.** All four policy tests in this commit read
   `drift_schemas/drift_schema_v1.json` as a file. A test that reflects over `AppDatabase` passes on a
   tree whose snapshot was never regenerated — which is precisely the failure the `codegen` job exists
   to catch and which **does not exist yet**.
6. **The `codegen` CI job is [N08-T06](../N08-the-migration-harness-and-the-codegen-job/N08-T06-the-codegen-ci-job.md),
   the next epic.** Until it lands, nothing in CI re-runs the generators and diffs them, so this
   commit's correctness rests on you running `make gen` on a clean tree and reading `git status --short`
   with your own eyes. 04 §3.6 calls that diff *"the single most valuable line of CI in the project"* —
   for one epic, you are it.
7. **`schema_versions.dart` is generated but not yet imported, and that is correct.**
   `database.dart` does not `import 'schema_versions.dart'` and does not call `stepByStep(...)` until
   N08-T01. An unreferenced generated library is not an analyzer error, and generated files are excluded
   from the gate.
8. **Read the DoD's *"compiles for the first time since T02"* as being about `make gen`, not about
   `dart analyze`.** T01–T07 each ran `build_runner`, so the tree compiled at every commit; what has not
   existed since T02 wrote `database.dart` is the **migration-artefact half** of the generated set —
   `schema_versions.dart` and `test/drift/generated/**` — and this is the commit that creates it. If
   your tree genuinely did not compile between T02 and T07, you registered table classes before their
   files existed: go back and apply T02's gotcha 1 rather than living with it.
9. **The two gates that prove §12.1 are exactly two, and this is the first.** The other is a widget test
   in N20 that the Treatment entry screen renders no pre-filled number. **Do not add a third** — in
   particular, do not add a source heuristic banning numeric literals near "withdrawal": it fires on the
   `CHECK` constraints in `treatments.dart` and on every fixture, and a gate that fires on correct code
   gets weakened until it fires on nothing.
10. **If you got it wrong and it has shipped, 04 §2.9 is the procedure and it starts with *stop the
    rollout*.** Never edit the committed step or the committed snapshot: phones that already ran it will
    not run it again, so an edit makes the fleet diverge into two schemas carrying the same version
    number — the worst state this system can be in. The repair is a **new** step at N+1, and if data was
    destroyed the app must be able to say so.
11. **Nothing in this task is time-shaped**, so there is no `test/domain/uk_zone/` case here. The epic's
    DST coverage is in T02 (converters), T03 (civil dates and the quad), T04 (`local_date` across
    spring-forward — the important one), T05 (elapsed millis and the clear date) and T07 (the seed's
    civil day). All of it runs under `TZ=Europe/London --tags uk-zone` in step 5 below; if any of it is
    red, **do not freeze.**
12. **`git log --oneline -- drift_schemas/` must print exactly one commit, forever.** That is why the
    epic merges with a merge commit rather than a squash: a squash collapses this commit into the other
    seven and makes *"the snapshot was committed exactly once"* unprovable from history.

### 5.5 What to read in the JSON before you commit

Open `drift_schemas/drift_schema_v1.json` and read it. Not skim — read it. It is the artefact this
whole epic exists to produce and it is the last moment anyone will look at it with fresh eyes.

- 23 tables plus `search_docs`, and no table you do not recognise.
- Every `CREATE TABLE` ends in `STRICT`.
- `treatment_withdrawals.days` has no default of any kind.
- The seven quad tables each carry three provenance columns and two CHECKs.
- `media_assets.relative_path` has three CHECKs.
- No column type is `REAL` anywhere: mass is integer grams, temperature integer milli-°C, and
  statistics are derived and not stored.

## 6. Constraints that bind this task

- **Irreversibility, above everything else.** This is the first of `04 §1`'s four things you cannot undo.
- **The commit is not split** (`00-README` §7.4) — and equally, nothing that is not a generated artefact
  or the one policy test may join it.
- **Generated code is never hand-edited** (`00-README` §7.3). `make gen` is the only way it changes.
- **The five safety rules** — §12.1 lands its *unpersistable* half here, on the artefact rather than on
  the source. A rule that drops to merely *documented* has been deleted, whatever the prose says.
- **Vocabulary** — one word per concept (`CLAUDE.md`). The banned words are banned in the commit message too: no `draft`, no `save()`, no `sync`, no `Error` as a failure name.
